Sprint Scope & Phased Deliverables
You are required to successfully deploy the Base MVP to meet your baseline sprint requirements. However, we expect Associates who want to demonstrate high performance to execute all three phases.

Phase 1: Base MVP (Mandatory Deliverables - P0) Completing this fulfills your minimum requirement for the sprint. The module must be fully responsive across mobile and desktop viewports.

Navbar: Logo aligned left, Navigation Links (Home, About, Services, Contact) aligned right. Must collapse into a hamburger menu or stacked layout on mobile.

Hero Section: High-conversion headline (e.g., "We Build Digital Experiences"), sub-headline, and a primary "Get Started" CTA button.

Services Module: A CSS Grid or Flexbox row rendering 3 service cards (e.g., SEO, Web Dev, Marketing).

Footer: Standard copyright text and social media icons.

Architecture Constraint: You MUST build this using raw CSS (Flexbox/Grid). UI frameworks (Bootstrap/Tailwind) are strictly restricted for this phase.

Phase 2: UI/UX Enhancements (Priority 1 Features) We strongly recommend completing this to demonstrate your technical capabilities.

Theme Controller: Integrate a Dark/Light mode toggle in the Navbar. Use vanilla JavaScript to toggle a CSS class on the <body> element.

Micro-Interactions: Configure hover states (color/scale shifts) for all CTA buttons. Implement z-axis lifting effects on the Service Cards upon mouse hover.

Sticky Navigation: Fix the Navbar to the top of the viewport during scroll events.

Phase 3: Stretch Goals & Optimization (Priority 2 Features) Engineers aiming for top performance reviews should execute these optimizations.

Tech Stack Migration: Refactor the module's styling architecture entirely into Tailwind CSS.

QA & Performance: Run a Google Lighthouse Audit (via Chrome DevTools). You must optimize the DOM until your "Performance" and "Accessibility" scores hit 100/100.

Glassmorphism: Utilize the backdrop-filter property to apply a "frosted glass" UI effect to the sticky Navbar.

Sprint 01 Technical FAQ
Is Bootstrap or Material UI approved for this sprint? No. For Sprint 01, we are auditing your raw CSS fundamentals. If you are executing Phase 3, you must use Tailwind. For Phases 1 and 2, stick to standard CSS files.

What if I lack Git/GitHub proficiency? Version control is a non-negotiable requirement. You are expected to upskill independently today (e.g., review YouTube tutorials on pushing code to GitHub). We do not accept .zip files under any circumstances.

What is the AI Policy for this module? You may use ChatGPT/Claude to assist with CSS logic, BUT you must understand the output. Blind copy-pasting is prohibited. All AI interactions must be logged in your Prompts.md file.

How should I handle copy and image assets? Utilize placeholder text (Lorem Ipsum) and royalty-free images (Unsplash/Pexels). We are auditing your architectural layout, not the copywriting.

What are the staging environment requirements? Localhost deployments are not accepted. Deploy your module to Vercel or Netlify (free tier is sufficient) and ensure the Live URL is functional before submission.
